Porter Foundations · v0.1 · shared by desktop (GPUI) and hub (Next.js)

A migration should never look more finished than it is.

1. Green means written Green appears only when a stage finished, wrote its output and opened no issues. For load, that means applied to the destination, not a dry run.
2. Unfinished looks unfinished Dry run is hatched with a dashed border. Skipped is hollow. Stale is greyed with a refresh mark. None of them share a shape or colour with done.
3. Problems sit next to their cause Every count links to its rows. Every invalid row says why, inline. Every state carries a glyph and a word, so colour is never the only signal.

Stage states

Chip = glyph + label. Glyph shapes differ (circle, square, ring, dashed), so states survive greyscale and colour-blindness.

Issue severity

error warning info
Error blocks Apply. Warning is shown on Apply and must be scrolled past. Info never changes a stage colour.

Issue resolution

open fixed-by-rerun handled-manually · note wont-fix
Open is the loudest. Resolved rows drop to muted but stay visible behind a filter; nothing is deleted.

Item status (per document)

Dots for dense tables (10px). Same shapes as the chips, so a row reads the same as its stage.
