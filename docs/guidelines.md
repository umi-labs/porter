# Porter Development Guidelines

This document provides guidelines and information for developing and maintaining the Porter data migration tool.

## Build/Configuration Instructions

### Prerequisites
- Rust toolchain (2024 edition)
- Cargo package manager

### Building the Project
```bash
# Build the project
cargo build

# Build for production
cargo build --release
```

### Running the Application
```bash
# Basic usage
cargo run -- --source umbraco --target payload --source-data test-data/umbraco.json --collection hotels

# With additional options
cargo run -- --source umbraco --target payload --source-data test-data/umbraco.json --collection hotels --interactive --verbose
```

### Command-Line Arguments
- `--source`: Source format (e.g., "umbraco")
- `--target`: Target format (e.g., "payload")
- `--source-data`: Path(s) to source data files (comma-separated for multiple files)
- `--output`: Output directory (default: "./seed")
- `--collection`: Collection name
- `--collection-path`: Collection path
- `--interactive`: Enable interactive mode
- `--dry-run`: Run without writing output files
- `--verbose`: Enable verbose output
- `--debug`: Enable debug output
- `--fixtures`: Enable fixtures

## Testing Information

### Test Structure
The project uses Rust's built-in testing framework. Tests are located in the `tests` directory and are organized by functionality.

### Running Tests
```bash
# Run all tests
cargo test

# Run a specific test
cargo test test_umbraco_to_payload

# Run tests with output
cargo test -- --nocapture
```

### Adding New Tests
1. Create a new test file in the `tests` directory or add tests to existing files.
2. Import the necessary modules from the porter library.
3. Write test functions with the `#[test]` attribute.
4. Use assertions to verify expected behavior.

### Example Test
Here's an example test that demonstrates migrating data from Umbraco to Payload:

```rust
use porter::sources::umbraco::UmbracoSource;
use porter::targets::payload::PayloadTarget;
use porter::adapter::{SourceReader, TargetWriter, TargetOptions};
use std::fs;
use std::path::Path;

#[test]
fn test_umbraco_to_payload() {
    // Setup
    let source = UmbracoSource;
    let target = PayloadTarget;
    let test_input = vec!["test-data/umbraco.json".to_string()];
    let test_output = "test-output";
    let options = TargetOptions {
        collection: Some("test-collection".to_string()),
    };

    // Clean up any previous test output
    if Path::new(test_output).exists() {
        fs::remove_dir_all(test_output).unwrap();
    }

    // Execute
    let docs = source.read_documents(&test_input).unwrap();
    assert!(!docs.is_empty(), "Should have read at least one document");
    
    target.emit_seed(&docs, test_output, &options).unwrap();
    
    // Verify
    let output_path = format!("{}/test-collection.seed.ts", test_output);
    assert!(Path::new(&output_path).exists(), "Output file should exist");
    
    let content = fs::read_to_string(output_path).unwrap();
    assert!(content.contains("GENERATED BY PORTER"), "Output should contain the generated comment");
    assert!(content.contains("export const seed ="), "Output should export the seed constant");
    
    // Clean up
    fs::remove_dir_all(test_output).unwrap();
}
```

## Additional Development Information

### Project Architecture
Porter is designed with a modular architecture:
- `SourceReader` trait: Implemented by source formats to read documents from input files.
- `TargetWriter` trait: Implemented by target formats to write documents to output files.
- Command-line interface: Defined in `cli.rs` using the clap crate.

### Adding a New Source Format
1. Create a new module in the `sources` directory.
2. Implement the `SourceReader` trait for your new source format.
3. Update the source selection logic in `main.rs`.

### Adding a New Target Format
1. Create a new module in the `targets` directory.
2. Implement the `TargetWriter` trait for your new target format.
3. Update the target selection logic in `main.rs`.

### Code Style
- Follow the Rust standard style guidelines.
- Use meaningful variable and function names.
- Add comments for complex logic.
- Use error handling with the `anyhow` crate for robust error management.
- Implement traits for modularity and extensibility.

### Error Handling
The project uses the `anyhow` crate for error handling. Functions should return `Result<T, anyhow::Error>` to propagate errors up the call stack.

### Logging
The project uses the `log` and `env_logger` crates for logging. Use appropriate log levels:
- `error!`: For errors that prevent the application from functioning correctly.
- `warn!`: For warnings that don't prevent the application from functioning.
- `info!`: For informational messages about the application's operation.
- `debug!`: For detailed debugging information.
- `trace!`: For very detailed tracing information.

### Performance Considerations
- Use the `rayon` crate for parallel processing when appropriate.
- Consider memory usage when processing large files.
